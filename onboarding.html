Welcome to Declarative Net Request - a powerful Firefox extension that gives you control over your web browsing. This extension lets you modify HTTP requests, block unwanted content, remove tracking parameters, and force HTTPS connections, all based on rules you define.

Thank you for using this extension. Take a look at the extension settings, where you can adjust more options than just the language.

Getting Started

Step 1: Enable Request Modification

This is required for the extension to work. After installation, you must grant permission for the extension to modify web requests:

  1. Click the extension icon in your Firefox toolbar
  2. Click Settings (or go to about:addons → declarativeNetRequest → Preferences)
  3. Click "Allow request modification"

Note: The toolbar popup will show a reminder if this permission is not yet granted. Rules will not apply until you complete this step.

Step 2: Understand the Default Rules

The extension comes with pre-configured rules that are already active. These include:

  • Privacy Protection: Removes common tracking parameters from URLs (such as utm_source, utm_medium, gclid, fbclid, and many others)
  • Security: Blocks connections to known dangerous CDN servers
  • Privacy Headers: Adds headers that tell websites not to track you

These rules work immediately once you enable request modification. You can review, edit, or disable them in Settings.

Step 3: Manage Rules for the Current Page

While browsing, you can quickly manage rules for the page you are on:

  • View active rules: Click the extension icon to see which rules are targeting the current page
  • Suspend a rule: Temporarily disable a rule for 1 hour (either globally or just for the current domain)
  • Add exceptions: Add the current domain to a rule's Except list to prevent it from applying
  • Block content: Block the current domain or specific page address with one click
  • View event log: See which requests have been blocked or redirected to HTTPS

Understanding How Rules Work

Each rule in Declarative Net Request has three main components:

1. What to Do (Actions)

Define what happens when a request matches your rule:

  • Modify request headers: Change headers sent to the server (e.g., add DNT: 1 for Do Not Track)
  • Modify response headers: Change headers received from the server
  • Remove GET parameters: Strip tracking or unwanted parameters from URLs
  • Set GET parameters: Add or override URL parameters
  • Block requests: Prevent specific requests from loading (ads, trackers, etc.)
  • Redirect to HTTPS: Automatically change HTTP to HTTPS for more secure connections

2. Where to Apply It (Targets)

Specify which websites and URLs the rule should affect:

  • Domains: Apply to specific websites (e.g., example.com, *.google.com)
  • URL patterns: Match specific paths using wildcards (e.g., *.example.com/track*)
  • Bookmark folders: Apply rules to all bookmarks in a specific folder
  • Except domains: Exclude certain domains from the rule

3. Which Requests to Affect (Resource Types)

Choose which types of resources the rule applies to:

  • Main page (main_frame)
  • Scripts
  • Stylesheets
  • Images
  • Fonts
  • Media (video/audio)
  • Fetch/XHR requests
  • WebSockets
  • Frames
  • Others

User Interface Overview

Toolbar Popup

Click the extension icon in your Firefox toolbar to quickly:

  • See all rules active on the current page
  • Suspend rules temporarily (1 hour)
  • Add the current domain to a rule's exceptions
  • Block the current domain or page address
  • View the event log of blocked requests
  • Access Settings

Sidebar

For a more spacious view, open the sidebar:

  • Go to Firefox menu → View → Sidebar → declarativeNetRequest
  • Or right-click the extension icon and select Show in Sidebar

The sidebar shows the same information as the popup but with more room for details.

Settings Page

Access comprehensive settings at about:addons → declarativeNetRequest → Preferences, or click Settings in the popup. Here you can:

  • Enable or disable request modification (required for rules to work)
  • View, add, edit, and delete rules
  • Enable or disable individual default rules
  • Import and export your rule configurations
  • Adjust extension behavior and preferences
  • Grant additional permissions as needed

Common Use Cases

Block Tracking Across the Web

Create rules to remove common tracking parameters from all websites. The default rules already handle the most common ones, but you can add more specific parameters used by particular services.

Block Specific Trackers or Ads

Create rules to block entire domains that serve ads or tracking scripts. This can significantly improve page load times and protect your privacy.

Force HTTPS Everywhere

Create redirect rules to automatically change HTTP connections to HTTPS for specific domains or across all websites.

Add Privacy Headers

Add headers like DNT: 1 (Do Not Track) or Sec-GPC: 1 (Global Privacy Control) to all your requests to signal your privacy preferences to websites.

Modify Requests for Specific Sites

Create rules that only apply to specific websites. For example, you might want to remove a specific tracking parameter that one site adds, or modify headers only for your bank website.

Privacy and Security

Your data stays on your device. This extension does not send any information off your computer. All your rules, settings, and browsing data remain local to your browser.

The extension uses Firefox built-in declarativeNetRequest API, which means:

  • Rules are applied efficiently by the browser itself, without a separate request listener
  • There is minimal performance impact on your browsing
  • Rules work even when the extension is not actively running

Note: Firefox does not report which specific rule was applied to each request. The extension event log and notifications therefore only cover blocked requests and HTTPS redirects.

More Information

Default Rules

The extension includes two types of default rules:

  • Enabled by default: Rules that are active immediately after enabling request modification. These include privacy protections and security features that are safe for most users.
  • Ready to enable: Additional rules that you can activate with one click in Settings. Review these before enabling, as they may affect how some websites work.

Important: Some rules can affect website functionality. If a site is not working properly, check if a rule is blocking or modifying something it needs. You can always suspend rules temporarily or add exceptions for specific domains.

Creating Your Own Rules

While the default rules cover many common use cases, you can create custom rules in Settings:

  1. Go to Settings → Add new rule
  2. Define what action to take (block, modify, redirect)
  3. Specify where to apply it (domains, URL patterns)
  4. Choose which resource types to affect
  5. Add any exceptions if needed

Tips for Effective Rule Management

Start with the default rules and adjust as needed:

  • Test rules one at a time: Enable a new rule and test if it works as expected before adding more
  • Use exceptions: If a rule breaks a website you need, add that domain to the rule exceptions rather than disabling the rule entirely
  • Temporary suspensions: Use the suspend for 1 hour feature to quickly test if a rule is causing an issue
  • Check the event log: The event log in the popup/sidebar shows which requests were blocked or redirected
  • Import/export: Backup your rules configuration using the Import/Export feature in Settings

Advanced Features

For power users:

  • Bookmark folder rules: Create rules that only apply to websites in specific bookmark folders
  • URL patterns with wildcards: Use * as a wildcard to match multiple URLs (e.g., *.example.com/*track*)
  • Multiple actions per rule: Combine multiple modifications in a single rule
  • Regular expressions: Use regex patterns for more complex matching (where supported)

Explore these features in Settings to create sophisticated rule configurations tailored to your needs.

Everyday Use: A Practical Guide

Check What Applies to a Page

Open the extension popup while viewing a website. It lists the rules that target that page and shows whether a rule is active or temporarily suspended. If no rules are listed, the page may simply have no matching rules. Browser-internal pages, such as extension settings, are not ordinary web pages and cannot be modified by these rules.

Test a Rule Before Keeping a Change

  1. In the popup, suspend a suspected rule for one hour, either everywhere or only for the current domain.
  2. Reload the page and check whether the problem is gone. Rules affect new requests; they do not undo requests that have already loaded.
  3. If the rule caused the problem, add the domain to that rule's Except list to keep the rule active on other websites, or edit the rule in Settings.

A temporary suspension ends automatically after one hour. An exception is permanent until you remove it in the rule editor.

Choose the Right Scope

A domain target covers requests to that domain and its subdomains, as well as files loaded by its pages from other domains. An address target is narrower: it affects requests to the matching page or file, but does not cover other files that page loads from elsewhere. Use a domain when you mean a whole site; use an address when you mean one specific page or file.

The popup's block actions have different effects too. Block domain blocks requests to the domain and its subdomains across websites. Block this address blocks only the exact page address. Both actions add an entry to a rule in Settings, where you can later change or remove it.

Know What the Defaults Send

Along with removing tracking parameters and blocking a list of dangerous CDN domains, the enabled defaults remove a few Facebook parameters and send two request headers: Sec-GPC: 1 (a Global Privacy Control signal) and Cookie-Preference: functional. These headers express preferences, but they are uncommon and may make your browser easier to identify. Review or disable them in Settings if you do not want to send them. The HTTP-to-HTTPS rule is available but starts disabled.

Understand the Event Log

The event log is not a full browsing history or a complete list of every rule match. In Firefox, it can show blocked requests and requests redirected to HTTPS; Firefox does not report every applied rule. A rule must also be set to write events to the log, and the required browser permission must be granted. Use the rule overview to see which rules target the current page.
